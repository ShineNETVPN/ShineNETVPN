1. Google Play VpnService Prominent Disclosure

This section provides explicit disclosure pursuant to Google Play's VPN Service Policy and Prominent Disclosure Requirements.

Android VpnService Declaration:
ShineNET VPN (com.shinecloud.vpn) utilizes the Android VpnService base class as its core, essential component to create a secure, encrypted device-level virtual private network tunnel to remote proxy and VPN endpoints.

By design and necessity, our application requires the Android VpnService API to:

  • Encrypt Outgoing & Incoming Traffic: Encrypt all network data originating from your Android device using industry-standard cryptography (TLS 1.3, AES-256-GCM, ChaCha20-Poly1305) before transmission over untrusted public Wi-Fi or cellular networks.
  • Bypass Network Tampering & Deep Packet Inspection: Obfuscate network packets to prevent unauthorized interception, surveillance, or unlawful throttling by network intermediaries.
  • Zero Data Interception: The VpnService tunnel established by ShineNET VPN operates strictly as an encrypted routing pipeline. The application does not monitor, inspect, log, or harvest any user payload, visited URLs, web traffic content, or packet metadata passing through this tunnel.
  • Prominent Consent: Before establishing any VPN tunnel, ShineNET VPN presents the system-level Android VPN permission dialogue requiring explicit user consent. You can disconnect or revoke VPN permissions at any moment directly from the application interface or Android system settings.

3. Limited Technical Operations & Local Data

To provide functional connectivity and recommend responsive servers, the client executes strictly limited, anonymous technical processes on your device:

3.1 Local Latency (Ping) Measurements

The application conducts localized round-trip latency checks (TCP/ICMP pings) directly to available candidate VPN servers to rank and display the lowest latency nodes. These measurements are computed locally on your device, stored temporarily in transient memory, and are never transmitted to external analytics servers.

3.2 Server IP Geolocation Lookup

To display server flags and country labels (e.g. 🇩🇪 Germany, 🇨🇦 Canada) next to server names, the app may query public IP geolocation endpoints using the server's public IP address only. Your personal IP address is never transmitted to geolocation services.

3.3 App Version Update Checks

On startup, the application periodically checks a public JSON manifest on GitHub to verify if an update or critical security patch is available. No user metadata or personal parameters are included in this query.

4. Server Infrastructure & Sourcing (ShineNETConfigs)

ShineNET VPN utilizes a decentralized, community-curated server model:

  • Public Configuration Feeds: Server endpoints and proxy routing configs are sourced dynamically from the open-source community repository located at https://github.com/shayanheidari01/ShineNETConfigs.
  • Transport Security: Configurations utilize robust transport layer security (TLS 1.3, XTLS Reality, or AEAD ciphers). Even the operators of individual community nodes cannot inspect the unencrypted payloads of your HTTPS web traffic.
  • Independent Verification: Because our configuration lists and client applications are open-source, anyone in the security community can independently verify and audit configuration integrity.

6. Cryptographic Standards & Security Safeguards

ShineNET VPN applies battle-tested, state-of-the-art encryption protocols designed to withstand both passive eavesdropping and active Deep Packet Inspection (DPI):

  • VLESS + XTLS Vision / Reality: Modern stateless proxy architecture eliminating TLS-in-TLS fingerprints, utilizing native TLS 1.3 ciphers.
  • Trojan: Traffic encapsulation inside genuine TLS sessions mimicking standard web browser traffic on HTTPS port 443.
  • VMess: V2Ray cryptographic transport protocol utilizing AES-128-GCM and ChaCha20-Poly1305.
  • Shadowsocks (AEAD 2022): Authenticated encryption with associated data ciphers providing fast, lightweight encryption.
